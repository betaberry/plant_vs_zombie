## 1. 意图分析

在浏览器中交付一个可试玩的 3D 第一人称「射击 + 种植塔防」沙盒垂直切片：两个本质不同的角色（豌豆枪手靠枪、太阳花靠设施），一张多街区城市地图，一种僵尸，阳光经济、商店、种植与铲子、存档、完整 HUD 与音频。目标是验证核心玩法循环（源文档 G-01～G-09），而非内容规模。

## 3. 功能需求

每组列出覆盖的源文档编号；验收标准即源文档对应条目的描述，以及第 14 章同编号测试用例。

### FR1 工程骨架与游戏循环（M0）
- FR1.1 Vite + TypeScript + Three.js（r160+）+ Rapier（`@dimforge/rapier3d-compat`）工程，可本地开发与构建。覆盖源文档 4.1。
- FR1.2 固定步长 1/60 s 逻辑 + 渲染插值；失焦暂停；可播种 PRNG。覆盖 TR-LOOP-01/03/04、AR-03。
- FR1.3 F3 调试面板（FPS、实体数、物理耗时、状态机、坐标、植物数）。覆盖 TR-LOOP-05。
- FR1.4 所有世界状态变更走统一 `GameCommand` 入口；植物、僵尸、玩家实现统一 `IAttackable`。覆盖 AR-01、AR-04、FR-AGG-07。

### FR2 第一人称移动（M0）
- FR2.1 Pointer Lock 视角、WASD、冲刺、跳跃、蹲下、灵敏度、头部摆动开关。覆盖 FR-MOV-01～05。
- FR2.2 不穿墙、不掉图（兜底传送）、台阶 ≤ 0.35 m 自动跨越、可上下楼梯。覆盖 FR-MOV-06/07、TC-MOV-01/02。
- FR2.3 `F` 交互（开门、拾取）。覆盖 FR-MOV-08（P1）。

### FR3 城市地图与导航（M1）
- FR3.1 300 m × 300 m、3～4 个相连街区（起点街区 / 商业街 / 住宅区 / 工业区），≥ 4 栋可进入建筑（含房间、走廊、楼梯），地标，封锁墙边界。覆盖 FR-MAP-01～03、06、07，9.2。
- FR3.2 ≥ 6 个重生点、≥ 12 个刷怪点（户外 + 室内埋伏），全部配置在 `map_city_01.json`。覆盖 FR-MAP-04/05。
- FR3.3 可种植区数据与统一查询 `canPlantAt(pos): {ok, reason}`。覆盖 FR-MAP-13/14，FR-MAP-15（P1）。
- FR3.4 航点图 + A* + 局部避让；连通性调试命令；坚果墙放置后局部重算并比较「绕路 vs 拆墙」代价。覆盖 TR-NAV-01～04。
- FR3.5 小地图、高价值区域。覆盖 FR-MAP-09/10（P1）。

### FR4 豌豆枪射击（M2，仅豌豆枪手）
- FR4.1 Hitscan、部位倍率（头 ×2.0 / 躯干 ×1.0 / 四肢 ×0.75）、距离衰减、扩散、后坐力、ADS、弹孔贴花（≤ 100 循环）。覆盖 FR-WPN-01～09、7.3.2、7.3.3。
- FR4.2 命中反馈：闪白、绿色豌豆汁粒子、音效、命中/击杀标记。覆盖 FR-WPN-10。
- FR4.3 队伍过滤：不伤己方植物，但植物会挡住射线；墙体阻挡射线；死亡僵尸碰撞体禁用。覆盖 FR-WPN-13、TR-HIT-01～05、TC-WPN-03/04。
- FR4.4 有限弹药：弹匣 24 / 备弹上限 240、换弹 2.0 s 可打断、备弹 0 时 HUD 红闪与提示、无近战。覆盖 FR-WPN-05/06/15～17、TC-WPN-01/05/08。
- FR4.5 受击方向指示、材质区分音效粒子。覆盖 FR-WPN-11/12（P1）。
- FR4.6 训练靶（静态假人），3 发躯干击杀。覆盖 M2 验收。

### FR5 僵尸 AI（M3、M5）
- FR5.1 普通僵尸属性与状态机：IDLE / WANDER / ALERT / CHASE / ATTACK / AMBUSH / BREAK / HIT_REACT / DEAD。覆盖 8.1、8.2、FR-AI-01～10。
- FR5.2 视觉射线感知（不隔墙）、听觉事件半径唤醒、屋内埋伏触发。覆盖 FR-AI-03～05、TC-AI-01～03。
- FR5.3 分离力避让、不卡墙、LOD 节流（> 60 m 降为 5 Hz，> 120 m 冻结）。覆盖 FR-AI-06/07/20。
- FR5.4 目标优先级「顺路」规则：玩家第一；坚果墙挡路则拆；豌豆射手 8 m 内且正在攻击自己则拆，玩家不可感知时 20 m 内也拆；太阳花苗 3 m 内顺手拆；玩家脱离感知则放弃拆植物。覆盖 FR-AGG-01～08、TC-AGG-01～06。
- FR5.5 个体差异、巡逻路线、门口聚集。覆盖 FR-AI-11～13（P1）。

### FR6 生命、死亡与重生（M3）
- FR6.1 HUD 血量、受伤红色渐晕、濒死效果、死亡倒地变灰、3 s 后在附近僵尸最少的重生点复活、3 s 无敌；阳光/物品/植物保留。覆盖 FR-HP-01～07、TC-HP-01。

### FR7 双角色（M4）

## 4. 非功能需求

- NFR1 性能：1080p 下 ≥ 60 FPS，最低 ≥ 45 FPS；Draw Call ≤ 150；同屏面数 ≤ 500k；纹理显存 ≤ 256 MB。覆盖 1.4、4.4、PT-01～03。
- NFR2 加载：首屏 ≤ 15 MB，3 秒内可进入可操作场景，其余资源后台加载。覆盖 G-01、4.4。
- NFR3 逻辑与渲染各自单帧预算 ≤ 8 ms。覆盖 TR-LOOP-02。
- NFR4 稳定性：连续游玩 15 分钟内存不持续增长；批量放置/摧毁 16 个设施时无明显卡顿（对象池）。覆盖 PT-04/05。
- NFR5 兼容性：Chrome / Edge 最新版、Windows 桌面；键盘 + 鼠标。覆盖 1.4。
- NFR6 可维护性：TypeScript 严格模式；逻辑 / 渲染 / UI 分层（AR-01～04）。
- NFR7 测试：Minimal 测试策略——对纯逻辑模块（配置校验、经济结算、药剂替换、目标优先级判定、`canPlantAt`、伤害结算、弹药/换弹）按需求逐条写单元测试，每个组件至少一条正常路径测试；用 Vitest。
- NFR8 安全与隐私：纯本地单机，无网络请求、无账号；存档只存在 `localStorage`。

## 6. 假设

- 寒冰射手虽标为 P2，但按 M5 交付项一起实现（理由见第 2 节）。
- 源文档 6.3 的 KPI（击杀耗时、阳光流速、弹尽率、豌豆射手存活时长等）是**调参目标**：在数值配置上按源文档 7.4 的平衡账对齐，但本次不把需要真人长时间试玩才能测出的 KPI 当作自动化验收门槛。KPI-01（3 发躯干击杀）与 TC-SUN-01（20 s +300）这类可计算的指标仍按测试验证。
- `docs/里程碑验收记录.md` 中的截图/录屏需要真人在浏览器中试玩生成；本次以勾选清单与自动化测试结果为主，截图项标注为待补。
- 性能指标（NFR1～NFR4）以 F3 调试面板读数与实现手段（实例化、合批、对象池、LOD）为依据；最终 FPS 数值需在你的机器上用浏览器实测确认。
- 下载 CC0 资源需要联网；Kenney 的资源包是 zip 格式，下载后只取用需要的文件。
