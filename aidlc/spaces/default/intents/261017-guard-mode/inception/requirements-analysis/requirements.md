## 1. 意图分析

现有游戏是无压力、无目标的沙盒。新增一个独立的「守卫模式」：守住地图中心的核心房子，一波一波打退僵尸，有胜负。原来的城市沙盒保留为「练习模式」，行为不变（D2-01、D2-14）。

## 3. 功能需求

### FR1 模式与入口
- FR1.1 主菜单分为「练习模式」和「守卫模式」两个入口；练习模式与现在的游戏完全一致（D2-01、D2-14）。
- FR1.2 守卫模式流程：主菜单 → 守卫模式 → 选难度（简单 / 标准 / 困难）→ 选角色（豌豆枪手 / 太阳花）→ 进入新地图 [Q4]。
- FR1.3 有守卫模式存档时，守卫模式入口提供「继续」与「重新开始」（重新开始需二次确认）。
- 验收：两种模式能分别进入；练习模式的现有单元测试与行为不受影响。

### FR2 螺旋同心环地图（FR2-MAP-01～07）
- FR2.1 新配置 `map_ring_01.json`：3 圈（外 r=50 m、中 r=32 m、内 r=16 m）× 2 层（地面 + 高架），环道宽 ≥ 8 m，中心 12 m × 12 m 核心房，4 个外圈入口，每圈之间 2 个坡道，2 个层间楼梯，玩家出生点在核心房旁（文档2 §5.2）。
- FR2.2 僵尸必须沿环道绕行，不能穿墙抄近路；最短路程约 95 m、最长约 190 m（±20% 可接受）。
- FR2.3 环道全部满足可种植条件（坡度 ≤ 15°），`canPlantAt` 在环道上可用。
- FR2.4 航点图覆盖两层、坡道和楼梯，连通性检查 0 个不连通航点；核心房内不放航点（FR2-MAP-02、FR2-MAP-07）。
- FR2.5 视觉地标：塔楼、水塔、集装箱堆场（FR2-MAP-06，P1）。先交纯功能版（几何体 + 占位色块），再补美术细节（R2-07）。
- FR2.6 配置校验按地图类型区分：城市地图沿用现有规则；环形地图校验自己的必需字段（入口数、圈半径、核心位置、刷怪点组）。
- 验收：地图校验通过；寻路测试证明从任一入口到核心外墙都有路径，且路径长度在 FR2.2 范围内。

### FR3 核心房（FR2-CORE-01～07）
- FR3.1 核心是一栋房子，有独立碰撞体；僵尸进不去，玩家可以进去（FR2-CORE-02/03）。
- FR3.2 核心实现统一的可被攻击接口，所有僵尸类型（含 BOSS 与小鬼）都能攻击它（FR2-CORE-04）。
- FR3.3 核心血量按难度：简单 4000 / 标准 5000 / 困难 7000（D2-07）；不能被修复（FR2-CORE-05）。
- FR3.4 HUD 显示核心血条；低于 50% 时闪红并播放心跳音（FR2-CORE-06）。
- FR3.5 4 个损坏阶段：完好 → 窗户破碎 → 墙体裂痕 → 冒烟 → 崩塌（FR2-CORE-07，S2）。
- 验收：伤害结算测试证明普通僵尸打核心为 10 伤害/秒 × 难度倍率；血量 0 触发失败。

### FR4 波次引擎（FR2-WAVE-01～04）
- FR4.1 波次之间按 `F` 立即开始下一波；同时有 30 秒倒计时，到时自动开始（D2-08）。第 1 波开始前同样适用。
- FR4.2 每波僵尸数：第 1 波数量 + (波数 − 1) × 递增，不超过单波上限（文档2 §4.3；线性递增）。
- FR4.3 类型按波次逐步引入：普通 → 路障 → 铁桶 → 铁门 → 橄榄球 → 撑杆跳 → 读报（文档2 §4.2 ②）。
- FR4.4 波内刷新间隔每波 ×0.9（文档2 §4.2 ③）。
- FR4.5 开放入口数：1–2 波 1 个、3–4 波 2 个、5–6 波 3 个、7 波起 4 个，再受难度入口上限约束（简单 2 / 标准 3 / 困难 4）（文档2 §5.3）。
- FR4.6 本波所有僵尸（含 BOSS 和小鬼）被消灭后，这一波清场；清空最后一波即通关。
- FR4.7 HUD 常驻显示：当前波数 / 总波数、下一波倒计时（波次中显示剩余僵尸数）、核心血量（FR2-WAVE-03）。
- FR4.8 刷怪判据改为「视锥外 且 距玩家 > 15 m 且 不在玩家指向核心方向的 45° 内」（文档2 §5.4）；练习模式沿用原刷怪导演。
- FR4.9 波次引擎写成纯逻辑模块（输入时间、按 F、清场、失败事件，输出要刷的僵尸与状态），便于单元测试。
- 验收：单元测试覆盖每档难度的波数、每波数量与上限、入口开放曲线、倒计时与按 F、清场判定。

### FR5 三档难度（D2-15，文档2 §4.3）
- FR5.1 `challenge.json` 写入三档难度的全部参数：波数 5/8/12、首波数量 4/6/8、递增 +2/+3/+3、单波上限 16/30/40、僵尸血量倍率 0.8/1.0/1.25、对玩家伤害倍率 0.7/1.0/1.3、对核心伤害倍率 0.7/1.0/1.3、倒计时 30 s、入口上限 2/3/4、阳光收入倍率 1.2/1.0/0.8、核心血量 4000/5000/7000。
- FR5.2 阳光收入倍率作用于击杀奖励和太阳花 / 太阳花苗产出；阳光上限仍是 999（FR2-ECO-01/02）。
- FR5.3 同屏僵尸上限仍为 40（原性能预算）；困难档单波上限 40 正好顶到这个值。
- FR5.4 配置校验：每档参数齐全、取值为正、单波上限 ≤ 40、波数 ≥ 1。
- 验收：配置校验测试；难度倍率作用的单元测试。

### FR6 失败与重开（FR2-FAIL-01～06）
- FR6.1 核心血量归零 → 失败；所有玩家阵亡 → 失败。单人时玩家死亡即失败（D2-02，§4.5 推论）。
- FR6.2 有 ≥ 1 名玩家存活时，阵亡玩家不能复活（为多人预留，单人下不触发）（D2-03）。
- FR6.3 失败后显示失败界面，然后从当前波重新开始，不回第 1 波（D2-04）。
- FR6.4 重开保留：已种植物、当前阳光、永久强化、限时药剂、已购物品；清除：本波已生成的全部僵尸（含 BOSS 和小鬼）、掉落道具；波数与难度不变（D2-05、FR2-ECO-05）。
- FR6.5 核心血量不因重开而恢复（FR2-CORE-05「整关总预算」）[assumption：文档2 没有明说重开时核心血量是否重置；按「不可修复、整关总预算」理解为不恢复。若核心血量为 0 导致失败，重开时恢复到该波开始时的血量，否则无法继续]。
- 验收：单元测试覆盖失败判定、重开时保留与清除的内容。

### FR7 僵尸目标规则（守卫模式）（FR2-AGG-01～06，D2-11、D2-12）
- FR7.1 波次进行中，僵尸的默认目标是核心：沿航点走到核心外墙后攻击房子。
- FR7.2 例外一（仇恨）：被玩家或植物攻击过 → 反击该来源；仇恨保持规则沿用 `deaggroWhenPlayerLost`（40 m / 8 s）。
- FR7.3 例外二（接近）：玩家进入 12 m、或植物进入 8 m → 攻击最近的那个。
- FR7.4 例外三（受阻）：被坚果墙挡住且无法绕行 → 拆墙。
- FR7.5 被拆掉植物后，该僵尸的仇恨转移，视为被攻击（FR2-AGG-06，P1）。
- FR7.6 作用域：只在守卫模式波次进行中生效；练习模式继续玩家优先（原 8.3）。
- FR7.7 僵尸远处降频 / 冻结（LOD）不能让冲向核心的僵尸停住：守卫模式下按「到玩家或核心的较近距离」计算 LOD。
- 验收：纯逻辑测试覆盖三种例外与默认冲核心、作用域切换。

### FR8 巨人僵尸 BOSS 与小鬼僵尸 [Q2][Q6]
- FR8.1 巨人僵尸（`gargantuar_zombie`）只在最后一波出现 1 只，与该波其他僵尸一起刷出；必须被消灭才算清场。
- FR8.2 体型约普通僵尸 2 倍；血量 简单 3000 / 标准 4000 / 困难 6000（不再叠加难度血量倍率）；移速 0.6 m/s；目标规则同 FR7。
- FR8.3 攻击：抡电线杆砸击，前摇约 1 s，范围伤害；一击砸毁植物和坚果墙；对核心 200 / 次，对玩家 40 / 次（再乘难度伤害倍率）。
- FR8.4 血量降到一半时，向前方防线扔出 1 只小鬼僵尸（只扔一次）。
- FR8.5 小鬼僵尸（`imp_zombie`）：血量 50，移速 2.5 m/s，落地后直奔核心，目标规则同 FR7；不会在普通波次单独刷出。
- FR8.6 新模型：巨人僵尸（大体型、电线杆、背上的小鬼）和小鬼（小体型），沿用现有程序化低多边形风格与姿态动画系统，有专属动作：走路、抡杆砸击、扔小鬼、受击、倒地。HUD 在 BOSS 出现后显示 BOSS 血条。
- FR8.7 所有数值写进 `zombies.json` / `challenge.json`；移速仍低于玩家步行速度（D-29 不变），沿用现有配置校验。
- 验收：纯逻辑测试覆盖半血只扔一次、砸击对坚果墙一击摧毁、BOSS 只在最后一波刷出。

### FR9 经济与商店（FR2-ECO-01～05）
- FR9.1 阳光来源与上限沿用现有规则，乘以难度阳光收入倍率（FR5.2）。
- FR9.2 按 `B` 随时开商店（含波次中），不暂停，原价（D2-09）。
- FR9.3 守卫模式不刷地面补给点、训练假人和城市埋伏僵尸（D2-10）。
- 验收：守卫模式会话中不存在补给点。

### FR10 结算与失败界面 [Q3]
- FR10.1 清空最后一波后，显示「守卫成功」结算界面（难度、通关用时、剩余核心血量），选项：返回主菜单 / 再来一局。不做记录、不发奖励。
- FR10.2 失败界面显示失败原因（核心被毁 / 玩家阵亡）与当前波数，选项：重开当前波 / 返回主菜单。
- FR10.3 全部文案为简体中文，集中在字符串表。

### FR11 存档 [Q5]
- FR11.1 守卫模式使用独立存档键（与练习模式的 `pvz3d.save.v1` 分开），两种模式互不覆盖。
- FR11.2 存档内容：难度、角色、当前波数（存在波次之间的状态）、核心血量、阳光、物品与种子、永久强化、限时药剂剩余时间、已种植物（位置、类型、血量）。
- FR11.3 存档时机：波次清场时、购买、种植、暂停、退出、关闭页面。波次进行中退出时，读档后从当前波重新开始（该波的僵尸不保存）。
- FR11.4 通关或「重新开始」后删除守卫模式存档。
- 验收：存档读写测试；两种模式存档互不影响。

### FR12 HUD 与小地图
- FR12.1 守卫模式 HUD：波数 / 总波数、倒计时或剩余僵尸数、核心血条、BOSS 血条（出现时）、「按 F 开始下一波」提示。
- FR12.2 小地图支持环形地图：显示圈层、入口（标出已开放的）、核心位置和玩家朝向。

## 4. 非功能需求

- NFR1 性能：同屏 40 只僵尸 + 16 个植物时，沿用原预算（≥ 45 FPS、Draw Call ≤ 150、三角面 ≤ 500k）。巨人僵尸与小鬼新增的 Draw Call 单独列出；需要在浏览器 F3 面板实测。
- NFR2 不回归：现有全部单元测试保持通过；`npm run build`（含类型检查）通过。
- NFR3 可配置：守卫模式所有数值都在 JSON 配置中（AR-02），配置校验覆盖新字段。
- NFR4 测试（Minimal 策略）：波次引擎、失败与重开、目标规则、BOSS 能力、难度参数、存档等纯逻辑各有单元测试，每个组件至少一条正常路径加两条边界用例。
- NFR5 本地单机，无网络请求。

## 5. 约束

- 技术栈不变（TypeScript + Three.js + Rapier + Vite + Vitest）。
- 不修改 `需求文档.md` 与 `需求文档2.md`。
- 航点网格目前只有平面且障碍只支持轴对齐矩形：高架层与弧形环墙需要显式的额外节点 / 边，或用多段矩形近似（代码扫描结论）。
- 地图与系统同期交付（D2-18），先交纯功能版地图。

## 6. 假设

- FR6.5 中「重开时核心血量不恢复」的理解，以及核心归零时的例外处理。
- 「所有玩家阵亡」在单人下按「玩家死一次即失败、重开当前波」实现，不给复活次数（Q2-06 先按 0 次）。
- 守卫模式中原来的「玩家死亡 3 秒后复活」流程被失败与重开流程取代。
- BOSS 只出现在最后一波，不叠加难度血量倍率（血量已按难度单独给出）；简单档 5 波时也在第 5 波出现。
- 小鬼僵尸 2.5 m/s 仍低于玩家步行速度 4.5 m/s。
- 新增巨人僵尸与小鬼的模型会让僵尸 Draw Call 超过之前的 24 个，但仍需满足总预算 ≤ 150。
